Schema diffs and safe migrations for Postgres and MySQL

Vector compares two databases, or a database and the schema files in your repo, and writes the SQL that takes one to the other. It orders the statements, plans the locks and refuses to drop data unless you ask.

$brew install vectorsql/tap/vector

Read the quick start See it in CI

One static binary for macOS, Linux and Windows. Postgres 12 to 17, MySQL 8.0 and 8.4. MIT licence.

Three passes, one SQL file

Vector never guesses from your migration folder. It reads what is really in the database, compares it with what you want, and writes the steps in between.

  1. 01

    Introspect

    Both sides are read into the same model: from pg_catalog and information_schema, or from the .sql files in your repo.

  2. 02

    Diff

    Objects are matched by name, then by shape, so a renamed column is offered as a rename instead of a drop and an add.

    Drop invoice_totals, alter, recreate. The order comes from the graph, never from file names.

  3. 03

    Plan

    Each statement gets the lock it takes and an estimate from table size. Anything over your budget is split or flagged.

    -- 20261121_0932_invoices_due_on.sql
alter table invoices
  add column due_on date not null
  default current_date + 30;
-- lock: access exclusive, est. 0.2 s
alter table invoices
  alter column amount_cents type bigint
  using amount_cents::bigint;
-- lock: none
create index concurrently
  invoices_customer_due_idx
  on invoices (customer_id, due_on);

A review step for every schema change

vector check runs the same diff against staging on each pull request, posts the plan as a comment and fails the build when the change would drop data or hold a lock past your budget.

# .github/workflows/schema.yml
on: pull_request
jobs:
  schema:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: curl -fsSL https://get.vectorsql.dev | sh
      - run: vector check --comment
        env:
          VECTOR_TARGET: ${{ secrets.STAGING_URL }}
0
No drift. The schema in the repo matches staging.
1
Drift with a safe plan. Comment posted, build passes.
2
Blocked change or lock over budget. Build fails.
